# 盤面の部門タブ化と、事務部門・全体確認の移植

対象 issue: [#13](https://github.com/dd47114711-design/voicelogi/issues/13)
作成日: 2026-08-28

## 背景

盤面は土木・運輸の2部門を縦に並べて表示している。legacy にあった**部門タブ**
（`legacy/webapp/index.html:31-47`）が移植されておらず、**事務部門**と**全体確認**も
新実装に存在しない。

これは移植漏れではなく、意図的な除外だった。`scripts/seed-master-data.mjs:10` に
「事務部門(office)の4名は配車盤の対象外のため除外している」と明記されている。
「事務は配車に関係ない」という判断で範囲外にしたもの。今回この判断を覆して戻す。

### 現状

| 層 | 状態 |
| --- | --- |
| `supabase/migrations/0001_init_schema.sql:6` | `staff.department` の CHECK が `('土木', '運輸')` のみ |
| `supabase/migrations/0005_placement_department.sql:7` | `placement_slots.department` も同じく2値 |
| 実データ | 土木 11人 / 運輸 20人 / 事務 0人 |
| `app/page.tsx:14-15` | `DepartmentBoard` を2つべた書き |
| `components/board/department-board.tsx:12` | 型も `'土木' \| '運輸'` |
| 全体確認 | 相当するものが無い |

### 要件の出どころに関する注意

`legacy/webapp/README.md:27` は「上部：土木部門、下部：運輸部門」と**縦積み前提のまま**で、
タブ化と事務部門の追加に追いついていない。README は通常「動く仕様書」として扱うが、
**この件に限っては `index.html` と `app.js` の実装が正**であり、そちらから要件を起こす。

legacy の該当実装:

- 部門タブ: `index.html:31-47`、タブ見出しのカウントは `app.js:817-825`
- 事務部門: `app.js:1176-1198`（現場・ダンプを持たない、氏名+出退勤のみ）
- 全体確認: `app.js:833-878`
- 事務の初期4名: `app.js:264-269`

## スキーマ

新規マイグレーション `supabase/migrations/0007_office_department.sql`:

- `staff.department` の CHECK 制約に `'事務'` を追加する
- **`placement_slots.department` は変更しない**

`placement_slots` を据え置くのは意図的な制約である。事務員は現場にも配置枠にも入らない
（`app.js:1176`「現場・ダンプを持たない、氏名+出退勤のみのシンプルな一覧」）。
ここを開けると「事務部門の現場」という存在しない概念が作れてしまうため、
DB 側で塞いだままにする。

RLS は既存ポリシーがテーブル単位で効いているため、追加・変更は不要。

## 型による不変条件の保護

`lib/board/department.ts` を新設する。

```ts
// 現場・配置枠を持つ部門。placement_slots に入りうるのはこれだけ。
export type BoardDepartment = '土木' | '運輸'

// 従業員の所属。事務は配置枠を持たないので BoardDepartment には含まれない。
export type StaffDepartment = BoardDepartment | '事務'
```

`SiteGroupList` / `UnassignedStaffGroup` / `RestingStaffGroup` など、配置枠を前提とする
コンポーネントとクエリの引数は `BoardDepartment` に変更する。事務を渡すと型エラーになるため、
上記のスキーマ側の制約がコンパイル時にも守られる。

現在 `'土木' | '運輸'` をインラインで書いている箇所を、この型に置き換える。

## データ投入

事務4名（黒瀬とも美・山内舞・江川愛梨・谷口扶美代）を
`scripts/seed-master-data.mjs` の `staffSeed` に追加する。

現在の冪等性は「staff / vehicles / sites のいずれかに既にデータがあれば何もしない」という
全体単位の判定になっている。本番DBには既に31人が入っているため、このままでは事務4名が
永久に入らない。**「未登録の従業員だけを挿入する」方式に変更**し、新規環境と既存環境の
両方を同じ経路で扱えるようにする。既存判定のキーは `(name, department)` の組とする。
現行の実データに同姓同名は存在しない（黒瀬姓が5名いるが下の名前はすべて異なる）。

10行目の「事務部門(office)の4名は配車盤の対象外のため除外している」というコメントは
実態と合わなくなるので削除・修正する。

## タブ

`?dept=` を Server Component で読む方式を採る。タブバーは `<Link>` を並べるだけの
Server Component で、クライアント状態を持たない。

- `app/page.tsx` が `searchParams`（Next.js 16 では Promise）から `dept` を読む
- `dept` が未指定または未知の値のときは土木にフォールバックする
- 選択中のタブの盤面だけをレンダリングする。見ていない部門のクエリは走らない

| `?dept=` | 表示 |
| --- | --- |
| （なし） / `doboku` | `DepartmentBoard department="土木"` |
| `unyu` | `DepartmentBoard department="運輸"` |
| `office` | `OfficeBoard`（新規） |
| `summary` | `SummaryBoard`（新規） |

タブ見出しには legacy に倣って出勤・退勤の人数を出す（運輸は使用台数も）。
このカウントは3部門すべての集計を必要とするため、**タブバー専用の独立した Suspense 境界**に
入れる。盤面本体の描画をカウント取得で待たせないための分割である。

URL に状態を持たせる副作用として、タブ切替のたびにサーバ往復が発生する。
リロードしても同じタブに戻ること、選択中の部門のクエリしか走らないことを優先した。

## 事務盤面

`components/board/office-board.tsx` を新設する。

現場もダンプも持たないため `CollapsibleBoard`（開閉ツールバー）は使わない。
出勤・退勤の名前札を並べるだけの単純な構造にする。札の色は既存仕様どおり
出勤=白 / 退勤=赤 で、`components/ui/name-tag.tsx` をそのまま使う。

事務員が0人のときは「事務員が登録されていません。」と表示する
（`app.js:1195` と同じ文言）。

事務部門には「休み」グループを作らない。休みは「どの配置枠にも居ない人」の概念であり、
配置枠を持たない事務には当てはまらないため。legacy も全員を1つの一覧に並べている。

## 全体確認

`components/board/summary-board.tsx` を新設する。部門ごとの集計カードを並べる。

| カード | 内容 |
| --- | --- |
| 土木 | 出勤 / 退勤 / 稼働現場 |
| 運輸 | 出勤 / 退勤 / 稼働配置 / 使用中 / 空車 / 整備 / 車検 / 故障 / 使用停止 |
| 事務 | 出勤 / 退勤 |

「稼働現場」「稼働配置」は legacy の `deptActiveGroupCount`（`app.js:801-810`）に合わせ、
**人が1人以上入っている配置枠**、または運輸の場合は**運転手なしのダンプが駐車している配置枠**
を数える。空の配置枠は数えない。

各カードに「〇〇を開く」リンクを置き、対応するタブへ遷移させる。

**カード1枚 = 1コンポーネント = 1 Suspense 境界**とする。運輸カードは車両6種の集計を
伴って最も重いため、これを束ねると土木・事務のカード表示まで止まる。

## エラー処理

既存クエリの方針を踏襲する。Supabase のエラーは日本語メッセージを付けて `throw` し、
Suspense 境界の外側で Next.js のエラー境界に委ねる。集計を握り潰してゼロを表示しない
（実際に0人なのか取得に失敗したのか区別できなくなるため）。
