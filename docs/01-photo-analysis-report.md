# KoeHaisha フェーズ1 写真分析レポート

対象：現場で実際に毎日使われている「出欠・配車札ボード」の写真2枚（ほぼ同じアングル、微妙にタイミング違い）

このレポートは実装前の分析専用です。ここに書いた内容をご確認・訂正いただいた上で、設計（全体構成／DB設計／画面設計／操作フロー／フォルダ構成／使用技術）に進みます。

## 1. ボードの物理構造

- 金属製の名札差し込みラック（木製の上枠付き）。上から順に**7段の棚**があり、各棚の溝に短冊状の札を差し込んで使う。
- 4段目と5段目の間、また7段目の手前に**空の棚が1段ずつ**ある（予備スペース、または増員用の余白と推測）。
- 右側に girisiコルクボードと、赤いケースに入ったタブレット端末が壁に設置されている（既存の連絡事項掲示・別デジタル機器が既にある可能性）。
- 札は白地に黒文字が基本、一部だけ**赤地に文字**（後述）。
- 列によっては札の間を赤い縦線（紐/シール）で結んでいるように見える箇所がある＝同じまとまり（グループ）であることを示す目印の可能性。

## 2. 札1枚＝1情報、「人名＋会社名＋車両番号」の3点セットが基本単位

2段目〜5段目に繰り返し現れるパターンから、次の組み合わせが1ユニットとして並んでいることが読み取れます。

同様の3点セットが2〜5段目に横に何組も並んでいます（読み取れた組み合わせの一部）：

## 3. 段（行）ごとの役割（ご確認いただいた内容を反映）

**このボードは「土木」と「運輸」という2つの部門を1枚で管理していることが確認できました。**

- **1段目＝土木作業員の列**：渡邊啓一、黒瀬裕大観、川脇諒、桒野修平、小野一世、村田広実、垣﨑和幸の7名は**土木の作業員**（ご本人確認済み）。会社名・車両番号が付いていないのはトラック配車の対象外だから、という理由で説明がつく。
  - 同じ1段目の右側にある (株)イワサキ／貨物バン5703／軽トラ3663 は、土木作業員とは別枠で、**運輸側の予備車両・貸切先**を並べていると推測（要最終確認だが、フェーズ1のブロッカーではないため後続の設計で吸収可能）。
- **2〜5段目＝運輸部門の実働欄**：現場に出ているドライバーの「個人名＋発注会社＋車両番号」の3点セットが並ぶ、**運輸の配車・出面（でづら）欄**。
- **6段目**：空。増員時の予備スペースと推測。
- **7段目（最下段）＝運輸の協力会社／待機置き場**：右側に協力会社名の列（フジタ建設、日本物流サービス、大森工業、永井運輸、フェアロード、小田組）と、右端に**赤札（本日休み・欠勤の状態色、ご確認済み）で個人名5名＋「お休み」**の列。運輸ドライバーのうち「今日は稼働しない人」をまとめて置く**待機置き場**。

→ フェーズ1のデータ設計では、**「土木」「運輸」という部門区分**、および運輸側の「氏名＋会社＋車両」3点セット・待機置き場という構造を最初から前提に含める必要があります。

## 4. 色分けの意味（推測・要確認）

- 白地の札：通常の氏名・会社名・車両番号。
- **赤地の札＝「稼働状態（本日休み・欠勤）」を表す状態色**（ご確認済み）。最下段の黒瀬隆／黒瀬冨弘龍／黒瀬剛／秋山英行／水口経光、および「お休み」がこれにあたる。
  - 2段目の「長野進」の赤札も同じ状態色の一種と考えられる（本日は稼働ユニットの枠に居るが休み扱い、または元の待機位置から一時的に見えている状態など、細部は設計時に運用へ合わせて調整）。

## 5. 2枚の写真の差分からわかること

2枚の写真はほぼ同じボードですが、細部の札の並び・空き具合に違いがあります。これは机上の推測ではなく、**実際に日々（あるいは1日の中でも）札を差し替えて運用している証拠**です。つまり：

- 状態変更は「札を抜く→別の場所に挿す」という**物理的な移動だけ**で完結している。
- 特別な記録やログは残らず、**「今この瞬間どう並んでいるか」だけが正**という運用（＝スナップショット型の管理）。
- 熟練者は配置を見ただけで「誰が空いているか」「どの車が使われていないか」を一瞙で判断できる。

## 6. 現状の運用ルール まとめ

1. 情報の最小単位は「氏名札」「会社名札」「車両番号札」の3種類。
2. この3種を横に並べて差し込むことで「割当」を表現する（＝配置そのものがデータ）。
3. 空いている棚溝＝空車・未割当を意味する。
4. 下段に「待機／休み」置き場があり、稼働していない人の札を一時的にそこへ移す。
5. 色（白／赤）で何らかの区分（属人区分か稼働区分）を表している。
6. 更新は誰か（配車担当）が手で札を挿し替えるだけ。タップ1回に相当する動作で完結している＝**すでに「シンプルな1アクション運用」が確立している**。

## 7. 情報の流れ（想定される1日の業務）

1. 朝、配車担当がボード全体を見て「誰が空いているか」「どの車が空いているか」を確認する。
2. 依頼のあった仕事（会社・現場）に対して、空いているドライバー＋車両の札を組み合わせてユニットとして配置する。
3. 休みの人・仕事が終わった人の札は最下段（待機置き場）に戻す。
4. 日中に状況が変わったら都度差し替える（今日と昨日の写真がわずかに違うのはこのため）。
5. その場に居合わせた人（ドライバー含む）は、ボードを見るだけで自分の割当・他の人の状況を把握できる。

## 8. デジタル化にあたり「残すべき点」（最重要）

- **「氏名＋会社＋車両」を並べて見せる」という視覚構造そのもの**。1画面で全員・全車の状況が一覧できる感覚を崩さない。
- **操作は"挿し替える"＝1アクションで完結**。タップだけで完結させるというご要望と完全に一致。
- **色分けによる瞬間認識**（文字を読まなくても色で分かる）。
- **空き＝空欄という直感的表現**。
- **待機／休みをまとめて置く場所**という概念。
- 大きな文字・遠くからでも読める視認性（縦型タッチパネルでの再現が必須）。
- 「新システムを覚え直す」感覚をゼロに近づけること。

## 9. デジタル化で改善できる点（フェーズ1では実装しない・将来検討用メモ）

- 誰が・いつ・どの札をどう変更したかの**履歴が残らない**（紙は上書きされたら過去が消える）→ 将来的に変更ログを残せる。
- 札の**紛失・破損・置き間違い**のリスク（物理物ゆえ）。
- 事務所に行かないと状況が見えない（**遠隔からの確認ができない**）。
- 複数拠点・複数人が同時に見たり触ったりできない（1枚のボードは同時に1箇所でしか更新できない）。
- 将来の音声入力・配車最適化・請求書連携等とデータをそのままつなげられる（今は仕込みのみ、実装せず）。
