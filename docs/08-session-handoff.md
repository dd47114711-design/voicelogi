# KoeHaisha セッション引き継ぎメモ

このドキュメントは、セッションをリセット・引き継ぐ際にそのまま貼り付けて使える要約です。最新状況は各ドキュメント（docs/01〜07）を正としてください。

## 開発理念（最優先）

このシステムは「最新の配車システム」を作ることが目的ではありません。

目的は、現在会社で毎日行っている業務を、そのままデジタル化し、誰でも引き継げる仕組みにすることです。

優先順位は以下のとおりです。

1. 現場で毎日使えること
2. 年配の人でも迷わず操作できること
3. 今の紙運用を極力変えないこと
4. 段階的（フェーズごと）に完成させること
5. 将来の拡張性を残すこと

機能を増やすことより、現場でストレスなく使えることを最優先としてください。

KoeHaishaは業務改善ソフトではなく、**会社のノウハウを次世代へ引き継ぐためのシステム**である。

会長の仕事を奪うシステムではない。会長の仕事を引き継げる仕組みを作りたい――これが、このプロジェクトの本当の目的である。

## フェーズ1：完了

出欠札ボードのデジタル化。

- 土木／運輸の部門別に社員名札を表示、5状態（出勤／現場／空車／休み／その他）をタップで変更
- 「休み」は自動的に最下段の休みエリアへ移動
- 社員管理画面（`/admin`）：追加／編集／削除（ソフトデリート）／復活／並び替え／応援（`home_department`と`current_department`の分離により、本来の所属を変えず当日だけ他部門に配置可能）
- 管理画面・書き込み系APIは`ADMIN_PASSWORD`によるBasic認証で保護（出欠札ボード本体は保護対象外）
- 誤操作防止：状態変更直後に数秒間「元に戻す」トースト
- 端末構成：**Windowsミニ PC（常時起動・サーバー役）＋32インチ KTC MEGAPAD（Android、Chromeで接続する表示・操作専用端末）**に確定
- `webapp/deploy/`に自動起動・キオスク表示・バックアップのスクリプト（Windows／Linux）
- フェーズ1の完了基準は「コードが動くこと」ではなく「現場で毎日使えること」（`docs/03-phase1-readiness.md`）

## フェーズ2：進行中（2A実装中）

範囲を2つに分割し、**2A（マスタ管理）が正常に動くことを確認してから2B（当日の現場配置）へ進む**方針（ユーザー指示）。

### 確定した設計（`docs/07-phase2-design-v2.md`が最新・正）

- `Client`（取引先）→`Site`（現場）→`SitePrice`（現場ごとの車種別単価、履歴管理）の3層構造
- `Site.workCategory`（土木／運輸／舗装／その他）と`Site.orderCategory`（公共／民間／不明）に分離。**社員の`Department`（土木／運輸）とは完全に独立**（enum型も別、参照関係なし）
- 車種違い（4t車等）は別現場にせず、同一現場内で`SitePrice`を車種ごとに複数持たせる
- `Site`・`SitePrice`に`needsReview`／`reviewReason`／`reviewedAt`で要確認ワークフローを実装済み
- フェーズ2B（未着手）：`Employee.currentSiteId`（当日の現場配置）を追加予定。翌日の扱いは **(a)自動リセットせず引き継ぐ ＋ (c)手動の「本日リセット」ボタン（確認ダイアログ付き）** を採用。将来「前日配置を翌日にコピー」する機能を追加できる設計にしておく
- 現場検索は取引先名／現場名／区分／車種／備考を横断。フェーズ2Aは文字検索＋一覧のみ、「最近使用」「よく使用」はフェーズ2Bで追加
- 出欠ボードに「部門別／現場別」タブを追加予定（初期表示は部門別、休みの人は常に休みエリア優先）

### 単価データ分析（`docs/05-price-data-analysis.md`）

## このセッションで確立した進め方のルール

- 実装前に必ず設計書（docs/配下）を提示し、ユーザー承認を得てから着手する
- 各工程完了時に「実装内容・確認方法・残課題」を報告する
- 判断が必要な点は独断で決めず、その都度ユーザーに確認する
- ドキュメントは`docs/`に連番で蓄積する（01〜07、本ファイルが08）
- 動作確認は実際にビルド・型チェック・lint・ブラウザ操作（Playwrightでスクリーンショット）まで行う
- git commit／pushは工程ごとに行い、コミットメッセージに変更理由を明記する
- 元データ（`scripts/price_data.json`等）は絶対に書き換えず、整形結果は別ファイルに出力する
