# 開発原則（KoeHaisha）

このドキュメントは、担当するAI・開発者が変わっても開発品質を維持するための具体的なルール集です。`docs/08-session-handoff.md`の開発理念を、日々の実務レベルに落とし込んだものです。

## 原則一覧

1. **DBスキーマを勝手に変更しない** — 変更が必要な場合は設計書を提示し、ユーザーの承認を得てから実施する
2. **UIを勝手に変更しない** — 特に現場で使う画面（出欠ボード等）は、レイアウトや操作方法を変える前に必ず確認する
3. **フェーズを飛ばさない** — 前フェーズが「現場で毎日使えること」を満たしてから次に進む（`docs/09-roadmap.md`参照）
4. **必ず「設計 → 承認 → 実装」の順で進める** — 実装を先行させない
5. **元データは必ず保持する** — 加工・整形した結果は別ファイルに出力し、元データ（例：`scripts/price_data.json`）は書き換えない
6. **互換性を壊す変更は事前確認する** — 既存データ・既存API・既存画面の挙動を変える場合は、影響範囲を提示してから着手する
7. **現場運用を最優先する** — 機能の多さより、現場でストレスなく毎日使えることを優先する
8. 各工程完了時に「実装内容・確認方法・残課題」を報告する
9. 動作確認はビルド・型チェック・lintに加え、実際にブラウザ操作（Playwright等）まで行う
10. git commit／pushは工程ごとに行い、変更理由をコミットメッセージに明記する
11. 判断が必要な点はAIが独断で決めず、その都度ユーザーに確認する
