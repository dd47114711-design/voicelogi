# 現場での運用セットアップ（フェーズ1完成条件への対応）

`docs/02-phase1-design.md` 7章の完成条件に対応する設定ファイル・スクリプト集です。タッチパネル端末（またはそれにつながる1台のPC）で、以下の手順を一度だけ設定すれば、あとは電源を入れるだけで使えるようになります。

## 0. サーバーをどこで動かすか（要方針決定・`docs/03-phase1-readiness.md` A8参照）

主な利用端末は32インチのKTC MEGAPAD（Android搭載タッチディスプレイ）を想定していますが、KoeHaisha本体（Next.jsサーバー）をAndroid上で直接動かすのは一般的ではありません。次のいずれかの構成を選ぶ必要があります。

- **案1**：別途、常時起動のPC（Windows/Linuxのミニパソコン等）を1台用意し、そこでサーバーを動かす。KTC MEGAPADはChromeブラウザでそのPCのアドレス（例：`http://<PCのIPアドレス>:3000`）を開くだけにする。以下の`linux/`・`windows/`のスクリプトはこの構成を前提にしています。
- **案2**：KTC MEGAPAD自体にNode.jsをインストールし、単体で完結させる（Android版Node.jsランタイム(Termux等)の利用が必要で、動作実績の確認が必要）。

**案1（別PCでサーバーを動かす）を推奨します。** タッチパネル本体が単なる「表示・操作端末」になるため、Android特有の制約を避けられ、将来Windows PCや他のタッチディスプレイに置き換える場合も、KoeHaisha側の設定を変えずに済みます。

KTC MEGAPAD側でのキオスク（全画面）自動表示は、Androidの「常時起動アプリ」設定や、Fully Kiosk Browser等のキオスク専用ブラウザアプリの利用を想定していますが、実機での検証はまだ行っていません。

## 1. アプリの自動起動

端末を起動したときに、KoeHaisha本体（Next.jsサーバー）を自動で立ち上げます。

- Linux（ラズパイ等のミニPC）: `linux/koehaisha.service` を参照。配置後、以下を実行して自動起動を有効にします。
  ```bash
  sudo cp linux/koehaisha.service /etc/systemd/system/
  sudo systemctl enable --now koehaisha
  ```
- Windows: `windows/start-koehaisha.bat` を、タスクスケジューラで「ログオン時に実行」に登録してください。

## 2. ブラウザのキオスクモード自動表示

サーバー起動後、ブラウザを全画面（キオスクモード）で自動的に開きます。

- Linux: `linux/start-kiosk.sh`
- Windows: `windows/start-kiosk.bat`

Chromeの実行ファイルパスは端末によって異なるため、各スクリプト内のパスを実際の場所に合わせて書き換えてください。

## 3. 再起動後も状態が保持される

データは `webapp/dev.db`（SQLiteファイル1つ）に保存されます。ファイルとしてディスクに残るため、アプリやOSを再起動してもデータは消えません。**このファイルを誤って削除・上書きしないよう、定期バックアップ（4番）と組み合わせて運用してください。**

## 4. データの自動バックアップ

`backup.sh` を1日1回、cron等で実行することで、日付付きのバックアップファイルを作成します。

```bash
# 例: 毎日深夜2時に実行
0 2 * * * /path/to/webapp/deploy/backup.sh
```

Windowsの場合はタスクスケジューラで同等の処理（`dev.db`を日付付きファイル名でコピー）を登録してください。

## 5. 通信がない環境での動作

KoeHaishaはアプリ・データベースとも同一端末内で完結しており、通常利用時に外部サービスへ通信することはありません（インストール・ビルド時のみインターネットが必要です）。オフライン環境で運用する場合は、事前に一度だけ以下を実行してNext.jsの利用状況送信（テレメトリ）を止めておくと安心です。

```bash
npx next telemetry disable
```

## 6. 誤操作防止（取り消し機能）

アプリ側の機能として実装済みです（状態変更後、数秒間「元に戻す」が画面下に表示されます）。追加の設定は不要です。
