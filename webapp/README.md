# 出勤・配車ボード(Phase1)

紙の出勤・配車札ボードを置き換える、32インチ縦型タッチモニター向けWebアプリです。
新規現場名の入力以外は、すべてタップ操作で完結します。

## 起動方法

ビルド不要の静的サイトです。任意の静的サーバーで `webapp/` を配信してください。

```bash
cd webapp
python3 -m http.server 8080
```

ブラウザ(Chrome推奨)で `http://localhost:8080/` を開き、右上の「全画面」ボタンで
キオスク表示にしてください。基準解像度は 1080×1920(縦)です。

社内サーバーで常時配信する場合は、`webapp/` フォルダを任意のWebサーバー
(nginx等)の公開ディレクトリにそのまま配置するだけで動作します。

## 画面構成(現場中心・折りたたみ可能なボード)

画面の主軸は「人」ではなく「現場」です。ダンプ20台・運輸現場15箇所程度
まで、文字を小さくせず縦スクロールで運用できることを前提にしています。

- ヘッダー中央：大きな時計(時:分:秒＋日付)
- 上部：土木部門、下部：運輸部門。それぞれ縦にスクロールする「現場ごとの
  行(レーン)」の集まり
- 運輸部門の見出しには車両20台の集計(使用中／空車／整備／車検／故障／
  使用停止／合計)を表示し、状態が確認できない車両があれば警告を表示
  します
- 1つの行(レーン)は「現場名の見出し(人数/台数＋開閉の▼▶)」＋「その現場
  に入っている人・車両の札を横並び(折り返しあり)で表示するエリア」で構成
  - 土木の行：作業員の名前札を複数並べる
  - 運輸の行：運転手の名前札とダンプ札の組を複数並べる(1現場に10人・
    10台入っても、横並び＋折り返しで表示・スクロールできます)
- 見出しをタップすると、その行だけ開閉できます(複数の行を同時に開いても
  構いません)。折りたたむと現場名・人数・台数だけの表示になり、15現場
  あっても見出しの一覧としてスクロールできます。各部門に「すべて開く」
  「すべて閉じる」ボタンもあります
- 現場だけでなく、次の行も自動的に現れます(該当者・該当車両がいるときのみ表示)
  - 現場未定：現場が決まっていない出勤者
  - 休み：退勤(お休み)状態の人。現場・ダンプの割当は保持したまま、
    表示だけこの行に移ります
  - 空車(運輸のみ)：使用可能なのに今日誰も使っていない車両
  - 整備／車検／故障／使用停止(運輸のみ)：その状態の車両
- 名前・現場・ダンプの文字は、実物の木札と同じく縦書きで表示(数字の連続
  だけ縦中横で横向きにまとめる)。長い現場名・車両名は自動で2列以上に
  折り返す
- 出勤=白、退勤=赤の名前札は確定仕様です

縦書き表示は日本語フォント(Meiryo/Yu Gothic/MS Gothic等)の縦書き用
グリフに依存します。該当フォントが無い環境では文字が正しく表示され
ない場合があるため、Windows標準の日本語フォントが入った環境での
利用を前提としています。

## 配車登録(現場→ダンプ→運転手→確認)

運輸部門の見出しにある緑色の「＋配車登録」ボタンから、新しい配車を
4ステップのウィザードで登録します(新規現場名の入力以外はすべてタップ)。

1. **現場**：登録済みの運輸現場(現在の割当台数つき)、または「現場未定」
   をタップ。ここでだけ「＋新規現場を追加」から現場名を入力できます
2. **ダンプ**：登録済み車両からタップ。使用可能な車両のみ選択でき、
   車検・整備・故障・使用停止の車両はグレー表示で選択できません。
   既に他の出勤中ドライバーが使っている車両を選ぶと、
   「〇〇は現在「△△」の××さんが使用しています。移動しますか？」
   という確認を挟みます
3. **運転手**：その車両の「通常運転手」がいれば「おすすめ」として一番上に
   表示し、他の運転手は一覧の下に続きます。出勤/退勤の状態が一目で
   わかり、既に別の現場に配車済みの人を選ぶと同様の移動確認を挟みます
4. **確認**：現場・ダンプ・運転手を確認して「この内容で登録」

登録すると、対象の現場行が自動的に開き、追加された人とダンプがすぐに
確認できます。登録完了メッセージの後、「同じ現場にもう1台追加」(現場選択
を省略してダンプ選択から再開)か「配車ボードへ戻る」を選べるので、1現場に
何台も連続登録するときに毎回現場を選び直す必要はありません。

配車登録は、対象者を自動的に「出勤」扱いにします(現場・ダンプを割り当てる
時点で今日その人が稼働する前提のため)。既に出勤済みの人を選んでも状態は
そのままです。

## 登録済み配車の変更・解除

運輸部門で、名前札またはダンプ札をタップすると、その人の配車を変更する
メニューが開きます(すべてタップ操作)。

- 現場を変更
- ダンプを変更(空いている車両からタップ。他の人が使用中の車両を選ぶと
  移動確認を挟みます)
- 運転手を変更(今の現場・ダンプをそのまま別の人に引き継がせます。元の
  人は現場未定・ダンプ未割当に戻ります)
- 出勤／退勤を変更
- 配車を解除(現場未定・ダンプ未割当に戻します。出退勤の記録や人員・
  車両の登録自体は削除しません)

土木部門は名前札をタップすると、出勤／退勤／現場を変更／休みへ移動の
シンプルなメニューが開きます。

## 二重登録防止

1人の運転手・1台のダンプが同時に2つの配車に入らないよう、配車登録
ウィザードと「ダンプを変更」「運転手を変更」のすべてで、既に使用中の
車両・既に配車済みの運転手を選んだ場合は移動確認を挟んでから、元の
割当を解除して新しい割当に置き換えます。通常ダンプ(`normalVehicleId`)と
当日の乗車ダンプ(`todayVehicleId`)は別フィールドで管理しており、当日
だけ別車両に変更しても通常ダンプの設定は変更されません。

## 出退勤記録(イベントログ＋CSVダウンロード)

名前をタップして「出勤」「退勤」を選ぶたびに、**過去の記録を上書きせず**、
操作イベントを1件ずつ追加で記録します(`state.attendanceLogs`)。

- 既に出勤中の人にもう一度「出勤」を選ぶ、既に退勤済みの人にもう一度
  「退勤」を選ぶ、といった同じ状態への再選択は、誤操作防止のため
  「現在すでに◯勤状態です。もう一度、◯勤時刻を記録しますか？」という
  確認画面を挟みます。「記録する」を選んだ場合のみイベントが追加され、
  「キャンセル」では何も記録されません。
- 記録が確定すると、「氏名／出勤(退勤) HH:MMを記録しました」という
  メッセージが画面上部に数秒間表示されます。

ヘッダーの「出退勤記録」ボタンから、

- 日次：◀前日／翌日▶ で日付を選び、「日次集計」(1人1行の集計表)と
  「操作履歴」(その日の全打刻を時刻順に一覧表示)をタブで切り替えて確認、
  その日の集計をCSVダウンロード
- 月次：◀前月／翌月▶ で月を選び、その月の集計(1人1日1行)をCSVダウンロード

のどちらも文字入力なしで操作できます。CSVはExcelでそのまま開け、列は
「日付／所属／氏名／出勤時刻／退勤時刻／勤務時間」です。

集計ルール(日次・月次共通)：

- その日の最初の`clockIn`を出勤時刻とする
- その日の最後の`clockOut`を退勤時刻とする
- 出勤・退勤の両方がある場合のみ勤務時間を算出する
- 出勤だけ／退勤だけの場合は、もう片方と勤務時間を空欄にする
- 退勤時刻が出勤時刻より前(打刻ミス等)の場合は勤務時間を算出せず、
  「要確認」と表示する
- 元のイベント(`state.attendanceLogs`)自体は集計の際も一切変更しない

## データの保存方法

ブラウザの `localStorage` に自動保存されます(保存キー:
`voicelogi_attendance_dispatch_v1`)。操作するたびに即時保存されるため、
再読み込みやパソコンの再起動後もその日の状態が残ります。

- `storage.js` … 保存処理だけを担当する層。将来サーバーDBへ移行する際は
  このファイルの `loadState` / `saveState` の中身を置き換えるだけで済むように、
  画面描画側(`app.js`)は Storage 経由でしかデータへアクセスしません。
- `seed.js` … 動作確認用の仮データ(初回起動時のみ使用)。実データが決まったら
  この中身を差し替えてください。
- `app.js` … 画面描画とタップ操作のロジック。

保存データを完全に消去して仮データからやり直したい場合は、ブラウザの開発者
コンソールで `Storage.clearState()` を実行し、ページを再読み込みしてください。

## データ構造

- 人員マスタ(`state.staff`)：氏名／所属(土木・運輸)／出退勤／通常ダンプ／
  当日ダンプ／当日現場／表示順／有効フラグ
- 現場マスタ(`state.sites`)：現場名／区分(土木・運輸・共通)／使用中フラグ／
  表示順／作成日時／利用回数(よく使う現場を上位表示するため)
- 車両マスタ(`state.vehicles`)：表示名／車両番号／車種／状態／表示順／有効フラグ
- 出退勤記録(`state.attendanceLogs`)：id／personId／personName／department／
  action(`clockIn`または`clockOut`)／timestamp／date／createdAt。
  人員マスタとは別に、出勤・退勤をタップするたびに1件ずつ追加する
  イベントログとして保持し、過去のレコードは上書き・削除しない。
  日次・月次の集計値(出勤時刻・退勤時刻・勤務時間)は、このイベントログ
  から都度計算して求める(集計結果自体は保存しない)

「通常ダンプ」と「当日の乗車ダンプ」は別フィールドで管理しており、当日だけ
別車両を選んでも通常ダンプの設定は変更されません。

## 今回実装していないもの(Phase2以降の検討事項)

- 請求書連携・日報連携・売上集計などの外部/後工程連携
- 音声入力、運行時間管理、複雑な権限管理
- 日付が変わった際の出退勤・現場・当日ダンプの自動リセット(現状は手動で
  出勤／退勤を切り替える運用を想定)
- サーバーDBへの移行(現状はブラウザローカル保存のみ。複数モニターでの
  状態共有はできません)
- 月次CSVは「1人1日1行」の集計であり、月間の合計勤務時間・合計出勤日数
  といった上位集計はまだ行っていません
- 旧バージョン(1人1日1レコード形式)で保存されたデータは、起動時に
  自動でイベントログ形式へ変換されます(`app.js`の`migrateAttendanceLogs`)
- 現場行の開閉(折りたたみ)状態はブラウザを開いている間だけ保持し、
  再読み込みでは初期状態(全展開)に戻ります。配車データ自体は保存されます
- 配車登録ウィザードのステップ1(現場選択)は、登録済みの運輸現場・現場
  未定・新規現場追加のみを選択肢にしています。「空車」「整備」「車検」
  「故障」「休み」は現場ではなく車両状態・出退勤の結果として自動的に
  決まる行のため、ウィザードの移動先としては選べない仕様にしています
  (車両状態の変更は車両札のタップ、休みへの移動は出退勤の変更から行えます)
