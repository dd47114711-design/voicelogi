# 出勤・配車ボード(Phase1)

紙の出勤・配車札ボードを置き換える、32インチ縦型タッチモニター向けWebアプリです。
新規現場名の入力以外は、すべてタップ操作で完結します。

## 起動方法

ビルド不要の静的サイトです。任意の静的サーバーで `webapp/` を配信してください。

```bash
cd webapp
python3 -m http.server 8080
```

ブラウザ(Chrome推奨)で `http://localhost:8080/` を開き、右上の「全画面」ボタンで
キオスク表示にしてください。基準解像度は 1080×1920(縦)です。

社内サーバーで常時配信する場合は、`webapp/` フォルダを任意のWebサーバー
(nginx等)の公開ディレクトリにそのまま配置するだけで動作します。

## 画面構成(現場グループ・3カラム表示)

画面の主軸は「人」ではなく「現場」です。ダンプ20台・運輸現場15箇所程度
まで、文字を小さくせず縦スクロールで運用できることを前提にしています。

- ヘッダー中央：大きな時計(時:分:秒＋日付)
- 上部：土木部門、下部：運輸部門。それぞれ縦にスクロールする「現場グループ」
  の集まり
- 運輸部門の見出しには車両20台の集計(使用中／空車／整備／車検／故障／
  使用停止／合計)を表示し、状態が確認できない車両があれば警告を表示
  します
- 1つの現場グループは、実物の札ボードと同じく**3カラム構成**です。
  - **左**：その現場の運転手(土木は作業員)の名前札を複数
  - **中央**：現場名の札(木札風の配色で、運転手札・ダンプ札とは
    見た目で区別できます)
  - **右**：その現場のダンプ札を複数(運輸のみ。土木は原則空欄で、
    運輸のダンプに乗っている日だけ表示されます)
  - 運転手とダンプは1組の小カードに結合せず、常に独立した札として
    表示・タップできます(1現場に10人・10台入っても、各カラムが
    横並び＋折り返しで表示・スクロールできます)
- 見出し(現場名・人数/台数＋開閉の▼▶)をタップすると、その行だけ開閉
  できます。**初期状態はすべて展開済み**です(常時「誰がどこにいるか」
  を見られることを優先しています)。折りたたみは補助機能で、各部門に
  「すべて開く」「すべて閉じる」ボタンもあります
- 現場だけでなく、次のグループも自動的に現れます(該当者・該当車両が
  いるときのみ表示)。特殊グループも同じ3カラム様式(中央に見出し札、
  該当する側だけ表示)で描画されます
  - 現場未定：現場が決まっていない出勤者(中央「現場未定」札＋左右とも該当分)
  - 休み：退勤(お休み)状態の人(中央「休み」札＋左に運転手・作業員札)
  - 空車(運輸のみ)：使用可能なのに今日誰も使っていない車両。運転手が
    誰も乗っていなくても、現場に駐車だけされている車両は空車に含みません
    (中央「空車」札＋右にダンプ札のみ)
  - 整備／車検／故障／使用停止(運輸のみ)：その状態の車両(同様に中央の
    札＋右にダンプ札のみ)
- 名前・現場・ダンプの文字は、実物の木札と同じく縦書きで表示(数字の連続
  だけ縦中横で横向きにまとめる)。長い現場名・車両名は自動で2列以上に
  折り返す
- 出勤=白、退勤=赤の名前札は確定仕様です

縦書き表示は日本語フォント(Meiryo/Yu Gothic/MS Gothic等)の縦書き用
グリフに依存します。該当フォントが無い環境では文字が正しく表示され
ない場合があるため、Windows標準の日本語フォントが入った環境での
利用を前提としています。

## 配車登録(現場→ダンプ複数選択→運転手複数選択→対応確認→一括登録)

運輸部門の見出しにある3つのボタンから操作します。

- **＋現場配車を作成**：新しい配車を5画面のウィザードで、**ダンプ・運転手とも
  複数選択**してまとめて登録します(新規現場名の入力以外はすべてタップ)
- **既存現場を編集**：現場を選んでから、下記の「現場グループの編集」を開きます
- **車両状態**：車両管理(車検・整備・故障・使用停止の変更)を開きます

ウィザードの流れ：

1. **現場**：登録済みの運輸現場(現在の割当台数つき)、または「現場未定」
   をタップ。ここでだけ「＋新規現場を追加」から現場名を入力できます
2. **ダンプ(複数選択)**：登録済み車両を複数タップして選びます(選択中の
   台数を上部に表示)。使用可能な車両のみ選択でき、車検・整備・故障・
   使用停止の車両はグレー表示で選択できません。既に他の現場で使用中・
   駐車中の車両を選ぶと、「〇〇は現在「△△」の××さんが使用しています。
   移動しますか？」という確認を挟みます
3. **運転手(複数選択)**：同様に複数人をタップして選びます(選択中の人数・
   選択したダンプ台数を上部に表示)。選択したダンプの「通常運転手」が
   いれば「おすすめ」として一番上に表示されます。出勤/退勤の状態が
   一目でわかり、既に別の現場に配車済みの人を選ぶと同様の移動確認を
   挟みます
4. **人数と台数が一致しない場合**：登録前に「運転手は◯人、ダンプは◯台
   選択されています」という確認を挟みます。「選択を修正」か、余った方を
   「未割当」として残したまま「未割当を含めて登録」できます(余ったダンプは
   運転手なしでその現場に駐車、余った運転手はダンプなしでその現場に配置)
5. **対応関係の確認**：通常ダンプの組合せを優先し、残りは選択順で仮に
   対応させます。行をタップするとその人のダンプを選択中の車両の中から
   変更できます。「この内容で一括登録」で確定します

退勤中の人が選択に含まれる場合は、登録の最後に「出勤を記録して配車」か
「配車だけ登録(出退勤はそのまま)」を選べます(配車登録だけで出勤打刻を
自動追加することはありません)。

登録すると、対象の現場グループが自動的に開き、追加された人とダンプが
すぐに確認できます。登録完了メッセージの後、「同じ現場に追加登録」
(現場選択を省略してダンプ選択から再開)か「配車ボードへ戻る」を選べるので、
1現場に何台も登録するときに毎回現場を選び直したり、1件ずつ繰り返したり
する必要はありません。

## 個別の配車変更・現場グループの編集

運輸部門で、名前札またはダンプ札をタップすると、その人(その車両を
運転している人)の配車を変更するメニューが開きます(すべてタップ操作)。

- 現場を変更
- ダンプを変更(空いている車両からタップ。他の人が使用中の車両を選ぶと
  移動確認を挟みます)
- 運転手を変更(今の現場・ダンプをそのまま別の人に引き継がせます。元の
  人は現場未定・ダンプ未割当に戻ります)
- 出勤／退勤を変更
- 配車を解除(現場未定・ダンプ未割当に戻します。出退勤の記録や人員・
  車両の登録自体は削除しません)

運転手が乗っていない状態で現場に駐車中のダンプ札をタップすると、
「運転手を割り当てる」「現場から外す(空車に戻す)」「車両状態を変更」
のメニューが開きます。

**現場名の札(中央)をタップすると、その現場グループ全体の編集メニュー**が
開きます。1人ずつではなく、複数の人・車両をまとめて追加・解除できます。

- 運転手(作業員)を追加／外す(複数選択可)
- ダンプを追加／外す(複数選択可。運輸のみ)
- 運転手とダンプの組合せを変更(運輸のみ。運転手を選んでから車両を選び直します)
- 現場名を変更
- 現場を終了(その現場の全員・全車両の割当を解除します。現場自体は削除
  されず、翌日以降も同じ現場名を選び直せます)

土木部門は名前札をタップすると、出勤／退勤／現場を変更／ダンプを選択(変更)／
休みへ移動のメニューが開きます。「ダンプを選択」は、土木の作業員が当日だけ
運輸のダンプに乗る場合(下記「部門をまたぐダンプ乗車」)に使います。ダンプを
選んでいる土木作業員は、名前札の右側にダンプ札も表示され、そのダンプ札を
タップすれば運輸と同じ配車編集メニュー(現場・ダンプ・運転手の変更や解除)を
開けます。土木部門の見出しにある「＋現場配置を作成」から、現場を選んで
複数の作業員を一括配置することもできます(ダンプ選択のステップはありません)。

## 部門をまたぐダンプ乗車(土木↔運輸)

「通常運転手」が休みの日や出張の日などに、別の人がそのダンプに乗ることが
あります。中でも、運輸の運転手だけでなく**土木の作業員が代わりにダンプへ
乗る場合**にも対応しています。

- 車両マスタの「通常運転手」は`normalVehicleId`で人ごとに固定していますが、
  当日だけ違う人が乗る場合は、その人の名前札(土木は「ダンプを選択」、
  運輸はダンプ札のタップ)から乗車するダンプを選ぶだけで済みます
- 空車判定・車両サマリー(使用中／空車の集計)は、部門を問わず「今日その
  車両に実際に乗っている人がいるかどうか」で計算します。そのため、土木の
  作業員がダンプに乗った日は、運輸部門の空車一覧・使用中カウントにも
  正しく反映されます(空車のまま残ったり、二重に使用中と数えられたりしません)
- 通常の運転手が出勤して戻ってくれば、他の人が乗っていたダンプを解除する
  ことで、また通常運転手が「通常ダンプ」から乗車を選び直せます

## 二重登録防止

1人の運転手・1台のダンプが同時に2つの配車に入らないよう、配車登録
ウィザード(複数選択)と「ダンプを変更」「運転手を変更」「現場グループの
編集」のすべてで、既に使用中(運転中)・既に駐車中・既に配車済みの運転手を
選んだ場合は移動確認を挟んでから、元の割当を解除して新しい割当に置き換え
ます。通常ダンプ(`normalVehicleId`)と当日の乗車ダンプ(`todayVehicleId`)は
別フィールドで管理しており、当日だけ別車両に変更しても通常ダンプの設定は
変更されません。

## 出退勤記録(イベントログ＋CSVダウンロード)

名前をタップして「出勤」「退勤」を選ぶたびに、**過去の記録を上書きせず**、
操作イベントを1件ずつ追加で記録します(`state.attendanceLogs`)。

- 既に出勤中の人にもう一度「出勤」を選ぶ、既に退勤済みの人にもう一度
  「退勤」を選ぶ、といった同じ状態への再選択は、誤操作防止のため
  「現在すでに◯勤状態です。もう一度、◯勤時刻を記録しますか？」という
  確認画面を挟みます。「記録する」を選んだ場合のみイベントが追加され、
  「キャンセル」では何も記録されません。
- 記録が確定すると、「氏名／出勤(退勤) HH:MMを記録しました」という
  メッセージが画面上部に数秒間表示されます。

ヘッダーの「出退勤記録」ボタンから、

- 日次：◀前日／翌日▶ で日付を選び、「日次集計」(1人1行の集計表)と
  「操作履歴」(その日の全打刻を時刻順に一覧表示)をタブで切り替えて確認、
  その日の集計をCSVダウンロード
- 月次：◀前月／翌月▶ で月を選び、その月の集計(1人1日1行)をCSVダウンロード

のどちらも文字入力なしで操作できます。CSVはExcelでそのまま開け、列は
「日付／所属／氏名／出勤時刻／退勤時刻／勤務時間」です。

集計ルール(日次・月次共通)：

- その日の最初の`clockIn`を出勤時刻とする
- その日の最後の`clockOut`を退勤時刻とする
- 出勤・退勤の両方がある場合のみ勤務時間を算出する
- 出勤だけ／退勤だけの場合は、もう片方と勤務時間を空欄にする
- 退勤時刻が出勤時刻より前(打刻ミス等)の場合は勤務時間を算出せず、
  「要確認」と表示する
- 元のイベント(`state.attendanceLogs`)自体は集計の際も一切変更しない

## データの保存方法

ブラウザの `localStorage` に自動保存されます(保存キー:
`voicelogi_attendance_dispatch_v1`)。操作するたびに即時保存されるため、
再読み込みやパソコンの再起動後もその日の状態が残ります。

- `storage.js` … 保存処理だけを担当する層。将来サーバーDBへ移行する際は
  このファイルの `loadState` / `saveState` の中身を置き換えるだけで済むように、
  画面描画側(`app.js`)は Storage 経由でしかデータへアクセスしません。
- `seed.js` … 初回起動時のみ使用する初期データ。土木9名・運輸20名(車番1〜19が
  10tダンプ、車番34-39が4tダンプ)の実名・実車番を登録済みです。人員や車両の
  構成が変わった場合はこの中身を書き換えてください。
- `app.js` … 画面描画とタップ操作のロジック。

保存データを完全に消去して仮データからやり直したい場合は、ブラウザの開発者
コンソールで `Storage.clearState()` を実行し、ページを再読み込みしてください。

## データ構造

- 人員マスタ(`state.staff`)：氏名／所属(土木・運輸)／出退勤／通常ダンプ／
  当日ダンプ／当日現場／表示順／有効フラグ
- 現場マスタ(`state.sites`)：現場名／区分(土木・運輸・共通)／使用中フラグ／
  表示順／作成日時／利用回数(よく使う現場を上位表示するため)
- 車両マスタ(`state.vehicles`)：表示名／車両番号／車種／状態／表示順／有効フラグ／
  `todaySiteId`(運転手が乗っていない状態で当日どこかの現場に駐車中の場合、
  その現場ID。運転手が乗ればnullに戻ります)
- 出退勤記録(`state.attendanceLogs`)：id／personId／personName／department／
  action(`clockIn`または`clockOut`)／timestamp／date／createdAt。
  人員マスタとは別に、出勤・退勤をタップするたびに1件ずつ追加する
  イベントログとして保持し、過去のレコードは上書き・削除しない。
  日次・月次の集計値(出勤時刻・退勤時刻・勤務時間)は、このイベントログ
  から都度計算して求める(集計結果自体は保存しない)

「通常ダンプ」と「当日の乗車ダンプ」は別フィールドで管理しており、当日だけ
別車両を選んでも通常ダンプの設定は変更されません。

## 今回実装していないもの(Phase2以降の検討事項)

- 請求書連携・日報連携・売上集計などの外部/後工程連携
- 音声入力、運行時間管理、複雑な権限管理
- 日付が変わった際の出退勤・現場・当日ダンプの自動リセット(現状は手動で
  出勤／退勤を切り替える運用を想定)
- サーバーDBへの移行(現状はブラウザローカル保存のみ。複数モニターでの
  状態共有はできません)
- 月次CSVは「1人1日1行」の集計であり、月間の合計勤務時間・合計出勤日数
  といった上位集計はまだ行っていません
- 旧バージョン(1人1日1レコード形式)で保存されたデータは、起動時に
  自動でイベントログ形式へ変換されます(`app.js`の`migrateAttendanceLogs`)
- 現場行の開閉(折りたたみ)状態はブラウザを開いている間だけ保持し、
  再読み込みでは初期状態(全展開)に戻ります。配車データ自体は保存されます
- 配車登録ウィザードのステップ1(現場選択)は、登録済みの運輸現場・現場
  未定・新規現場追加のみを選択肢にしています。「空車」「整備」「車検」
  「故障」「休み」は現場ではなく車両状態・出退勤の結果として自動的に
  決まる行のため、ウィザードの移動先としては選べない仕様にしています
  (車両状態の変更は車両札のタップ、休みへの移動は出退勤の変更から行えます)
- 配車登録ウィザードの「対応関係の確認」画面にある「組合せを変更」は、
  行ごとのタップによるダンプ変更として実装しており、専用の一括リセット
  ボタンは設けていません
