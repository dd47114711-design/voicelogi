# 出勤・配車ボード(Phase1)

紙の出勤・配車札ボードを置き換える、32インチ縦型タッチモニター向けWebアプリです。
新規現場名の入力以外は、すべてタップ操作で完結します。

## 起動方法

ビルド不要の静的サイトです。任意の静的サーバーで `webapp/` を配信してください。

```bash
cd webapp
python3 -m http.server 8080
```

ブラウザ(Chrome推奨)で `http://localhost:8080/` を開き、右上の「全画面」ボタンで
キオスク表示にしてください。基準解像度は 1080×1920(縦)です。

社内サーバーで常時配信する場合は、`webapp/` フォルダを任意のWebサーバー
(nginx等)の公開ディレクトリにそのまま配置するだけで動作します。

## 画面構成

- 上部：土木部門(名前＋現場)
- 下部：運輸部門(名前／現場／乗車ダンプ の3列)
- 名前をタップ：出勤／退勤／キャンセル
- 現場をタップ：現場一覧／現場未定／＋新規現場を追加／キャンセル
- 乗車ダンプをタップ：通常ダンプ／登録車両一覧／未割当／キャンセル
- ヘッダーの「車両管理」：車両ごとに 使用可能／車検／整備／故障／使用停止 を切替

## データの保存方法

ブラウザの `localStorage` に自動保存されます(保存キー:
`voicelogi_attendance_dispatch_v1`)。操作するたびに即時保存されるため、
再読み込みやパソコンの再起動後もその日の状態が残ります。

- `storage.js` … 保存処理だけを担当する層。将来サーバーDBへ移行する際は
  このファイルの `loadState` / `saveState` の中身を置き換えるだけで済むように、
  画面描画側(`app.js`)は Storage 経由でしかデータへアクセスしません。
- `seed.js` … 動作確認用の仮データ(初回起動時のみ使用)。実データが決まったら
  この中身を差し替えてください。
- `app.js` … 画面描画とタップ操作のロジック。

保存データを完全に消去して仮データからやり直したい場合は、ブラウザの開発者
コンソールで `Storage.clearState()` を実行し、ページを再読み込みしてください。

## データ構造

- 人員マスタ(`state.staff`)：氏名／所属(土木・運輸)／出退勤／通常ダンプ／
  当日ダンプ／当日現場／表示順／有効フラグ
- 現場マスタ(`state.sites`)：現場名／区分(土木・運輸・共通)／使用中フラグ／
  表示順／作成日時／利用回数(よく使う現場を上位表示するため)
- 車両マスタ(`state.vehicles`)：表示名／車両番号／車種／状態／表示順／有効フラグ

「通常ダンプ」と「当日の乗車ダンプ」は別フィールドで管理しており、当日だけ
別車両を選んでも通常ダンプの設定は変更されません。

## 今回実装していないもの(Phase2以降の検討事項)

- 日付が変わった際の出退勤・現場・当日ダンプの自動リセット(現状は手動で
  出勤／退勤を切り替える運用を想定)
